# Глава 1.1. Что такое Axum и его особенности

Axum - веб-фреймворк для создания HTTP-сервисов на Rust, созданный [командой Tokio](https://github.com/tokio-rs)  и построенный поверх [hyper](https://habr.com/ru/articles/917936/). Он предоставляет маршрутизацию, обработчики запросов, извлечение данных из запросов и т.д., а низкоуровневую работу с HTTP и асинхронным вводом-выводом делегирует другим библиотекам экосистемы Tokio.
## Почему axum

Axum создан командой Tokio и тесно интегрирован с экосистемой вокруг этого проекта. Вместо того чтобы реализовывать HTTP-сервер целиком внутри фреймворка, всё распределено по слоям.

| Крейт   | Слой                 | За что отвечает                                      |
| ------- | -------------------- | ---------------------------------------------------- |
| `tokio` | Async runtime        | Асинхронные задачи и сетевой I/O                     |
| `hyper` | HTTP                 | HTTP/1.1, HTTP/2, HTTP-соединения                    |
| `tower` | Service / middleware | `Service`, middleware, timeout, retry, rate limiting |
| `axum`  | Web framework        | Роутинг, handlers, extractors, интеграция с Tower    |

Это важный момент для понимания, Axum не реализует весь HTTP-стек самостоятельно, а использует готовые компоненты экосистемы. Его работа заключается в предоставлении удобных абстракций для написания REST API. Например, middleware из `tower` можно использовать независимо от Axum, а при необходимости можно работать с HTTP на более низком уровне через `hyper`.
## Почему Axum

- Большая экосистема - Axum интегрирован с экосистемой Tokio, что позволяет легко комбинировать его с нужными библиотекаи. Например, middleware из Tower можно использовать вместе с Axum, а HTTP-часть при необходимости настраивать через Hyper
- Меньше ошибок во время выполнения - многие вещи проверяются на этапе компиляции благодаря типам Rust
- Мало магии - Axum не пытается скрыть устройство приложения за большим количеством макросов. Основные части сервера представлены обычными структурами, функциями и trait'ами
## Альтернативы

* **Actix Web** - главный конкурент и самый зрелый фреймворк в экосистеме. Долгие годы возглавляет бенчмарки, богатая функциональность, макросы для роутов, встроенный акторный подход в основе. Из минусов собственная экосистема, репутация проекта пострадала из-за большого количества `unsafe` в ранних версиях и конфликта вокруг [мейнтейнера](https://habr.com/ru/articles/484436/) (сейчас код давно вычищен, но осадок в интернете остался)
* **Rocket** - более дружелюбный для новичка, максимум магии на макросах, похож на Flask из Python. Хорошо подходит для обучения и прототипов. Из минусов долгое время требовал nightly, релизы выходят редко, экосистема заметно меньше, а магия макросов мешает, когда нужно нестандартное поведение
* **Loco** - fullstack-фреймворк в духе Ruby on Rails, построенный поверх Axum. Предоставляет больше готовой инфраструктуры и задаёт структуру приложения, но ещё недостаточно зрелый для работы в production
## Первый hello world

Создаём проект:
```bash
cargo new hello-axum
cd hello-axum
```

Добавляем зависимости:
```bash
cargo add axum
cargo add tokio --features macros,rt-multi-thread
```

Теперь создадим HTTP-сервер:
```rust
// src/main.rs
use axum::{routing::get, Router};

#[tokio::main]
async fn main() {
    // Собираем роутер и добавляем маршрут GET /
    let router = Router::new().route("/", get(hello));

    // Открываем TCP-сокет
    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000")
        .await
        .unwrap();

    println!("Слушаем на http://{}", listener.local_addr().unwrap());

    // Отдаём http-сервер
    axum::serve(listener, router).await.unwrap();
}

async fn hello() -> &'static str {
    "Hello, World!"
}
```

Запускаем:
```bash
cargo run
```

Проверяем:
```bash
$ curl -i http://127.0.0.1:3000/

HTTP/1.1 200 OK
content-type: text/plain; charset=utf-8
content-length: 13
date: ...

Hello, World!
```

Теперь разберём программу по частям.
* `#[tokio::main]` - запускает асинхронную функцию `main` внутри Tokio runtime. Обычная `main` не может быть `async`, поэтому атрибут создаёт runtime и запускает в нём код. При желании то же самое пишется руками через [`tokio::runtime::Builder`](https://docs.rs/tokio/latest/tokio/runtime/struct.Builder.html)
* `Router::new().route("/", get(hello))` - строит таблицу маршрутов, `route` принимает путь и обработчик метода (`get`, `post`, `put` и т.д.). Скобки после `hello` не нужны, потому что мы передаём функцию самому Axum, а не вызываем её
* `TcpListener::bind(...)` - открывает TCP-сокет на указанном адресе. Здесь используется `tokio::net::TcpListener`, а не `std::net::TcpListener`, иначе поток выполнения бы блокировался
* `axum::serve(listener, router)` - запускает HTTP-сервер на переданном listener и передаёт запросы в `router`
* `.unwrap()` - извлекает значение из `Result` или завершает программу, если порт уже занят. Для учебного примера это допустимо, но в реальном приложении ошибки обычно обрабатывают явно
* `async fn hello() -> &'static str` - handler маршрута. Он возвращает строку, а Axum автоматически преобразует её в HTTP-ответ и устанавливает необходимые заголовки
